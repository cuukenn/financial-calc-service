# 11. 残值与留购价拆分；费用类型改用规范名

Status: resolved
Type: task
Priority: P3
数据角色: A 参与测算 —— 末期现金流与余额
Blocked by: —

## 背景

两处与 `AGENTS.md` §2.1「指标名称（规范名，不得同义混用）」的精神冲突：

1. 表单把「残值 / 留购价」放在同一个输入框。合同里这是两个金额：留购价（名义货价）是承租人
   期末取得所有权的对价，残值是租赁物在期末的预计价值（并涉及未担保余值）。
2. 费用类型是自由文本，任何同义写法都能进系统，报表侧无法稳定聚合。

## 落地记录（2026-11-11）—— 结论改为「改名，不拆分」

按 AGENTS.md §5 的 M-01：残值（未担保余值）不进入本口径的现金流，其唯一消费者是租赁内含
利率，而该指标需要额外的输入路径；直接加一个「残值」字段会变成装饰字段。因此本轮**不拆分**，
只把语义纠正过来：

- UI 标签「残值 / 留购价」→ **「留购价（名义货价）」**，并加一行说明（期末取得所有权的对价）；
- `residualHandling` → 「留购价处理」（SEPARATE 单独支付 / BALLOON_IN_RENT 摊入租金，语义不变）；
- 残值字段**暂不提供**，理由与恢复条件写在上面的 M-01 说明里；等 01 的内含利率支持未担保
  余值输入时再一并加。

费用类型受控词表未做（不影响任何金额，属 D 档展示约定，留待报表侧统一）。

## 原方案（不执行）

1. 拆成 `留购价（名义货价）` 与 `残值` 两个字段，并保留现有「残值处理」（并入租金 / 单独收取）
   的选择；确认口径后同步 §2.1 的术语表。
2. 费用类型改为受控词表（如 手续费 / 服务费 / 保险费 / 登记费 / 其他），允许「其他」但要求
   填备注；后端做一次宽松迁移（旧自由文本落为「其他」并保留原文）。
3. 结果区在指标表里同时展示两个金额，不再用一个「残值」概括。

## 验收标准

- 只填留购价（残值 0）与只填残值（留购价 0）两种场景的现金流与末期余额正确。
- 自由文本费用导入后不丢原始文本。
- i18n 两语文案对等，且不出现「残值/留购价」合并写法。
