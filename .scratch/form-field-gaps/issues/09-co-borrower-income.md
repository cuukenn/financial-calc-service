# 09. 房贷共同申请人 / 配偶收入与债务

Status: wontfix（2026-11-12 按 M-03 裁定关闭，见文末「裁定」）
Type: task
Priority: P3（C 档读数，不参与测算）
数据角色: C 监管读数 —— 不参与测算，DTI 由结果月供与收入派生
Blocked by: —

## 背景

`AGENTS.md` §2.2：单一申请人用本人可支配收入；**含配偶收入时须一并计入配偶债务**；共同申请
用主申请人 + 共同申请人可支配收入并计入其全部债务。现状只有「月可支配收入」与「其他月债务
支出」两个槽位，多申请人只能人工合并，最容易出的错就是「加了配偶收入、没加配偶债务」。

## 说明

按 2026-11-11 裁定的指标口径原则，本项属于 C 档监管读数：它不进入现金流与摊销表，
不应当被当成「核心指标」。保留它只因为 DTI 是放款前的合规判定，且 §2.2 明确要求配偶收入
与配偶债务同时计入。**不得**为它新增任何影响测算的字段。

## 要做什么

1. 「收入与债务」改为可增删的申请人列表：每个申请人有「月可支配收入」与「其他月债务支出」，
   首行为主申请人。
2. DTI 与月所有债务支出/收入比按**合计**计算，并在读数旁标注「含 N 位申请人」。
3. 任一申请人的债务未填而收入已填时给出提醒（不阻断，避免误拦）。

## 验收标准

- 两位申请人时，DTI = 月供 ÷（两人收入之和）；全部债务比 =（月供 + 两人债务）÷ 收入之和。
- 单申请人时与现状逐位一致。
- 未舍入原值判限（P-10）在合并后依然成立。

`web/src/components/MortgageIncomePanel.vue`、`web/src/components/ratioStatus.ts`、
`web/src/i18n/locales/*.ts`、`web/src/utils/ratio.ts`（复数收入/债务的十进制求和）。

## 裁定（2026-11-12）—— 关闭，上文「要做什么」「验收标准」不执行，存档备查

依据用户裁定的第二条核心要求（原文）：**「指标必须全部依赖测算要求的数据本身或测算结果、不得仅为了算指标加进来」**，与 `AGENTS.md` §5 M-03 的后半句（C 类读数「**不得为它引入不参与测算的字段**」）。

- 本 ticket 要新增的是「每位申请人的月可支配收入 / 其他月债务支出」多组槽位。这些槽位**不进入现金流、不进入摊销表、不改变任何一期金额或余额**，唯一作用是让 DTI 与月所有债务支出/收入比这两个 C 档读数算得更全 —— 即「仅为了算指标而加字段」，正是被禁止的那一类。
- 现有单申请人槽位（月可支配收入 / 其他月债务支出）**保留**：DTI 与全部债务比仍能由「摊销表的月供 + 已声明的收入/债务」复算（M-02 成立），并按 M-03 继续与测算结果分区展示、措辞不得让读数看起来像合同金额或收益率。
- 多申请人场景的既有做法不变，且这是**正确**做法：由申请人自己把收入与债务**合并成两个数**再录入。合并发生在录入侧，不进产品数据模型。
- 重新开启的条件：owner 明确裁定「C 档允许引入仪表字段」，并同步修订 `AGENTS.md` §5 的 C 档那一行；在此之前不得实现。
