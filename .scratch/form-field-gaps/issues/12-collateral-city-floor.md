# 12. 抵押物类型 / 房龄 / 城市首付下限

Status: wontfix（2026-11-12 按 M-03 裁定关闭，见文末「裁定」）
Type: task
Priority: P3
数据角色: C 政策提示 —— 不参与测算，不影响任何现金流
Blocked by: —

## 背景

全国首付下限已统一为 15%（2024-09 通知），但地方可更高；另外抵押物类型与房龄会影响评估
与贷款成数的实务上限。当前表单没有这些维度，只能按全国下限判，地方政策无法表达。

## 要做什么

1. 新增：抵押物类型（住宅 / 商用 / 其他）、房龄（年）、所在城市（可选）。
2. 城市可维护一个下限配置（默认 15%），命中城市时用该城市下限并**明确展示依据**。
3. 房龄只做提示（不阻断），避免把商业规则写死进代码。

## 验收标准

- 未选城市时回落到 15%，文案说明「按全国统一下限」。
- 选中配置了更高下限的城市时，闸门使用该值，且拦截文案写明来源。
- 房龄只影响提示，不影响提交。

## 涉及文件

`web/src/components/MortgageForm.vue`、`web/src/i18n/locales/*.ts`、
`web/src/utils/ratio.ts`（下限常量的来源收敛）。

## 裁定（2026-11-12）—— 关闭，上文「要做什么」「验收标准」不执行，存档备查

依据用户裁定的第二条核心要求（原文）：**「指标必须全部依赖测算要求的数据本身或测算结果、不得仅为了算指标加进来」**，与 `AGENTS.md` §5 M-03 的后半句（C 类读数「不得为它引入不参与测算的字段」）。本 ticket 比 09 更严重一层：它的验收标准第 2 条要把「城市下限」变成**提交闸门**的输入 —— 一个不参与测算的字段于是开始决定这笔测算能不能算出来，这是把仪表值伪装成测算要素。

- 新增「抵押物类型 / 房龄 / 所在城市 / 城市下限配置」全部不做。这些维度不改变任何一期现金流或余额。
- 保留现状：首付闸门按**全国统一下限 15%** 判（`AGENTS.md` §4，2024-09 通知），LTV 按**成交价与评估价孰低**判（§2.2，金规〔2026〕5号第十九条），两者都是 C 档读数、都不进 payload、不进引擎指标目录。
- 允许做的只有**文案**：在首付读数旁写明「按全国统一下限 15% 判；地方可更高，以当地规定为准」。文案不新增字段、不新增配置、不改变闸门数值。
- 城市下限属于报表 / 政策配置层（D 档邻域），不属于单笔测算计算器。
- 重新开启的条件：owner 明确裁定「允许引入仪表字段与仪表闸门」，并同步修订 `AGENTS.md` §5 的 C 档那一行；在此之前不得实现。
