# 15. 产品抽象与监管阈值下沉（A1 + A2，合并决策包）

Status: needs-owner（2026-11-14 立：本票是**决策提案**，不含实现；三项决策点见文末，拍板后拆实现 issue）
Type: grilling
Priority: P2
数据角色: 契约形状（A1）+ C 类读数的引擎化（A2）
Blocked by: —（本票本身就是解锁 A1/A2 的决策件）

## 背景

2026-11-11 扫描的两项遗留（arch A1 / A2），互相依赖：

- **A1 产品抽象**：房贷在引擎里只存在于前端的字段映射 + 一个契约测试（`MortgageForm` 把房贷要素映射成 `LeaseElement` 的 14 键 payload，R101/R137）。引擎不知道「这是一笔房贷」。
- **A2 阈值下沉**：首付 ≥ 15%、期限 ≤ 480 月、DTI ≤ 50%/60%（AGENTS.md §2.3「阈值即硬约束」）目前**只在前端**拦截（R107/R109：门槛由前端校验，文案如实写「引擎未校验」）。

**为什么 A2 依赖 A1**：引擎侧校验「首付 ≥ 15%」需要知道这笔是房贷——租赁单也有 downPayment/assetValue（CAS 21 链），没有产品身份就会对租赁单误报。没有 A1 就没有 A2。

**为什么 A1 一直没做**：契约冻结（「Plan 5 已冻结」，form-field-gaps spec 非目标），而 A1 的最小实现要往契约里加一个字段。

## 方案（拍板后按此拆实现）

### A1：ProductProfile，契约增量一个可选字段

- `CalculationRequestDto` 新增 `product`（可选，`LEASE` | `MORTGAGE`，**缺省 LEASE**）：既有调用方（含现有房贷前端，若不升级）逐字节不变——可选字段 + 缺省值是兼容性增量，不是契约破坏。
- `LeaseElement` / 引擎核心**不感知**产品：产品身份只进校验器装配层（`ValidatorChain` 按 profile 装配额外的校验器）与未来的结果区分区。测算内核（生成器/现金流/指标/§9.7）保持产品无关——R100「引擎对两个场景完全相同」不动摇，A1 只是在它之上**标注**这是哪类业务。
- `ProductProfile` SPI：`code()` + 该 profile 的附加校验器集合；内置 LEASE（无附加校验）与 MORTGAGE 两个实例。

### A2：MORTGAGE profile 的阈值校验器（WARN，读数而非拦截）

按下表逐项裁定，**只做引擎现有要素能算的**：

| 阈值 | 引擎可算？ | 裁定 |
|---|---|---|
| 首付比例 ≥ 15%（2024-09 通知） | ✅ `downPayment / assetValue`（CAS 21 链字段已在） | MORTGAGE profile 下 WARN：低于 15% 时发 `FCS-CALC-30xx` WARN，消息带实际比例 |
| 期限 ≤ 480 月（金规〔2026〕5号） | ✅ `periods` | 同上 WARN |
| DTI 50%/60% | ❌ 引擎无收入字段，且 **M-01 禁止**为读数引入不参与测算的字段 | **不下沉**：留在前端（R107/R109 姿态不变），提案明确记录这一豁免 |
| LTV | 无硬上限（§2.3 只列首付/期限/DTI） | 不做 |

- **级别用 WARN 不用 ERROR**：引擎的 ERROR 会让 `hasErrors() == true`（§9 校验语义 = 租金表不守恒需人工复核），把合规读数混进守恒语义会污染 §3.4 四项校验的信号。前端拦截（ERROR）+ 引擎读数（WARN）是两层不同职责：前端是提交闸门（纵深防御不变），引擎是随结果的合规披露（M-03：读数分区、不得像测算结果）。
- **R107/R109 文案的处理**：裁定的精神是「文案不得声称后端校验了它没校验的东西」。引擎开始发 WARN 后，「引擎未校验」七个字变成假话，文案必须随行为更新——这不是推翻 R107/R109，是它们要求的诚实性在行为变化后的自然延伸。**需要用户确认这一条**（决策点 ③）。

## 不做的

- DTI 下沉（M-01，见上表）。
- LEASE profile 的任何附加校验（v1 无监管阈值绑定租赁单）。
- 产品身份进入 `LeaseElement`（它不改变任何一期现金流，M-01 违背；只进请求层与校验装配）。

## 决策点（拍板即拆实现 issue）

1. **是否接受契约增量**：`product` 可选字段（缺省 LEASE）。接受 → 契约冻结按「兼容性增量」解冻一角；不接受 → A1/A2 永久搁置，本票 wontfix。
2. **引擎阈值发现的级别**：WARN（读数，推荐——理由如上）还是 ERROR（拦截；那前端门槛就降级为冗余，R107/R109 的「前端闸门」姿态实质性改变）。
3. **R107/R109 文案随行更新**：是/否。否 → 引擎发了 WARN 但文案仍说「引擎未校验」，自相矛盾，不可取——所以这一条实质上与决策点 2 绑定。

## 验收标准（拍板后具体化）

- 既有契约测试（含 MortgageForm 的 14 键 payload 契约测试）逐字节不动：`product` 缺省路径零变化。
- `product=MORTGAGE` + 首付 14% 的请求：`issues` 含一条 WARN、`hasErrors() == false`、测算照常返回。
- `product=LEASE`（或缺省）+ 任意要素：issues 与现状逐字节一致。
