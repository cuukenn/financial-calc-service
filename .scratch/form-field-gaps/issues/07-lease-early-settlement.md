# 07. 租赁提前结清试算（含违约金）

Status: resolved（2026-11-14 纯前端落地；口径见文末「落地记录」）
Type: task
Priority: P3
数据角色: B 结果派生 —— 由摊销表与结清日推出，不新增输入要素
Blocked by: —

## 背景

`AGENTS.md` §2.5 定义了剩余本金、实际计息天数、应计利息、提前还款违约金、结清金额，并给出
硬约束：**结清金额 = 剩余本金 + 截至结清日应计利息 + 合同约定违约金 − 已收未入账款项**，
不得按剩余期数租金总额打折。当前 UI 无入口，这些指标只是文档。

## 要做什么

1. 结果区新增「提前结清试算」：输入结清日（默认末期前一个月）与违约金率/金额。
2. 按 §2.5 的公式计算并展示四项分解（剩余本金 / 应计利息 / 违约金 / 结清金额）。
3. 应计利息按 P-03 日利率（年 ÷ 360）与「算头不算尾」计算，按 P-06 算至分。

## 验收标准

- 结清日落在某期中间时，拆分的利息与摊销表中该期利息可对账（差额 ≤ 0.01 元）。
- 违约金为 0 时结清金额 = 剩余本金 + 应计利息。
- 明确标注「按实际借款期间计息」（民法典第 677 条）。

## 落地记录（2026-11-14）

### 实现范围

与 ticket 08 共用一套结清试算（结果区新 Tab「提前结清试算」，租赁/房贷两场景共用 `SettlementPane` + 纯函数 `web/src/components/result/earlySettlement.ts`）：

- **结清日**：DatePicker，默认 = 末期前一期期末（「末期前一个月」的月频实现）；新结果到达自动重置。
- **违约金**：按比例（百分数口径输入）或固定金额二选一。
- **四项分解**：剩余本金 / 实际计息天数 / 应计利息 / 违约金 → 结清金额，另有罚息（房贷）、剩余期数、节省利息。

### 口径裁定（记录为标准）

1. **结清金额 = 剩余本金 + 应计利息 + 违约金（+ 罚息）**，各明细先算至分再求和（P-08）；不按剩余期数租金总额打折（§2.5 硬约束）。
2. **剩余本金** = 结清日承载期的期初余额（摊销表自带）；结清日恰逢某期期末日时归属**该期**（整期利息已借满、该期本金已到偿还日），只有结清日 = 首期期初才计零天。
3. **应计利息 = 剩余本金 × 该期期利率（`appliedRate`）× 实际计息天数 ÷ 该期天数**，算头不算尾、算至分（P-05/P-06）。天数按摊销表自己的计息基准：THIRTY_360 族用 30/360 差值、ACT 族用实际天数——**分子分母同基**，30/360 与 ACT_360 月频下与 P-03「日利率 = 年利率 ÷ 360」严格等价，ACT/365 等约定基准按 P-03「按约定执行」条款继承摊销表口径。
4. **整期逐位一致**：d = 该期天数时，应计利息与摊销表 `interestPaid` 是同一乘法同一舍入点，逐位相等——验收的「差额 ≤ 0.01 元」以 0 元达成。
5. **节省利息** = 结清日及之后各期 `interestPaid` 合计 − 应计利息（§2.5 节省利息，不打折不近似）。
6. 界面固定标注「按实际借款期间计息（民法典第 677 条）」与上述口径（验收第 3 条）。
7. **§2.5 公式的「− 已收未入账款项」项声明豁免**（代码自审补记，2026-11-14）：本产品没有
   收款流水/入账模型，「已收未入账」在 v1 数据模型下结构性为零；实现按
   结清金额 = 剩余本金 + 应计利息 + 违约金 + 罚息 四项。若未来引入收款流水，该项
   以独立减项回补，不得折进违约金或应计利息。
