# calc-engine：编排门面

## 职责边界

把请求变成结果的**唯一编排入口**：装配上下文 → 路由生成 → 现金流 → 指标 → 校验 →
实际利率表 → 结果。门面不拥有测算逻辑；它拥有的是**顺序、路由与失败语义**。
依赖 common / domain / rule，由消费者经本模块唯一出口使用（消费者如何暴露不在本技能范围）。

## 编排步骤

顺序不可重排，每步消费上一步产物。装配契约：

- 口径 code 必须命中注册表，缺失按引擎码报错（不是扩展点的「未找到」码）。
- 规则驱动方式必须携带规则集，否则报错；规则驱动生成器**每次运行新装**、单次运行专用。
- 校验链按产品身份选择：内核产品盲，产品语义只活在这一处选择上。

## 一次一解（性能纪律）

同一流不重复求根。运行内的求根台账记录「未舍入根 ↔ 流集合」；后续消费者先查台账，
未命中才自行求解。第二次求解的**唯一**合法理由是流不同——必须写明口径差别；
写不出差别即视为重复计算，须消掉。复用的是未舍入根，舍入率不进任何链式定价。

## 失败语义

- 可计算性失败（IRR 不收敛、表不闭合）答 `null` + WARN，永不抛出——「never fails here」契约。
- 校验 ERROR 不得降级 WARN；问题清单只在表的重建点合并一次。
- 每次运行的 runId 在入口生成，贯穿结果与日志。

## 核心日志分级

- **INFO**：run 生命周期（开始/结束，runId、耗时、期数、问题数、实际利率表是否产出）。
- **DEBUG**：步骤装配明细。
- **WARN**：诊断旁路（指标不可算、根不唯一、§9.7 拒绝）——**口径以问题清单为准，日志不双写**。
- **ERROR**：不属于本模块（编排只产出可预期失败）；系统异常归消费者层。

日志不得携带参与测算的中间数值；依赖只经 slf4j API（绑定由宿主提供）。

## 纪律

- 门面是**深模块**：新增能力优先做成端口的实现经注册表装配，而不是给门面加方法。
- 步骤增删属于口径相邻区：先在 `AGENTS.md` 裁定，再动代码。
- 性能改动受 §6 闸门约束：先在闸门测试里证明省时，再证明数值逐位一致。
