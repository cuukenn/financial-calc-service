# calc-domain：领域模型、端口与算法

## 职责边界

测算语义的全部载体：要素模型、摊销表模型、端口语义、内置算法、现金流构建、指标。
**框架无关 + 零日志**——这是被架构测试守卫的硬约束，不因便利而破。

## 分层（包即架构）

- `model`：不可变值对象。金额恒非负、方向字段表达收付；表以「重建」代替改写。
- `port`：**语义接口**——生成器、校验器、计息基准、日期调整、尾差策略、现金流构建器、
  求根器、规则集只读视图。接口的契约文档（不幂改、null 表不可算、校验器只报告不抛）
  是接口的一部分，与签名同等重要。
- `support`：端口的标准实现，按口径分包（算法/计息基准/日期调整/尾差/校验/现金流）。
  一个目录一种口径变体。

## 算法骨架（模板方法，不可破坏）

摊销生成 = 基类拥有期次循环、利息计提、期装配与守恒检查；子类只实现**本金分配**钩子。
生成器无状态、可共享；每次运行的期次序由基类保证严格递增——依赖此序的组件（如规则计划）
不得自行重排。

## 指标契约

每个指标是上下文上的只读函数：不可计算答 `null`（禁止给 0）；各自按口径舍入自己的输出；
分层消费（序号分层：直读表 → 求根 → 消费根），后层经上下文读前层结果，**不得重解同一流**。

## 校验链

表级验收检查，按错误码编号序运行；只报告问题、不改写表、不为业务失败抛异常；
对「哪种算法产出的表」无感知。守恒校验与生成器的守恒检查共用同一容差出处。

## 纪律

- 依赖只指向本模块与 calc-common；任何框架注解、JSON、日志、持久化类型不得进入。
- 新增字段前先回答：**它改变哪一期现金流或余额？** 答不出即不得加入要素模型。
- 数值精度、指标名称、标准要素的硬约束以 `AGENTS.md` §1–§3、§5 为准；本模块不复制数字。
